# ClientBook

客户联系人与商机记录。

需要Python 3.10 或更新版本，包含标准库 sqlite3。

查看命令帮助：

```sh
python3 app.py --help
```

启动本地服务：

```sh
python3 app.py serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/clients` 返回客户列表，首次启动时为空。
- `POST /api/clients/import` 直接接收 CSV 文件内容（请求体即文件字节），返回 JSON 导入报告。
- `POST /api/clients/batch-update` 接收 JSON，对勾选的客户批量修改来源、地区、行业、重要日期。
- 未知路径返回 404，已知路径不支持的方法返回 405。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/clients
curl -X POST --data-binary @clients.csv http://127.0.0.1:8080/api/clients/import
curl -X POST http://127.0.0.1:8080/api/clients/batch-update \
  -H 'Content-Type: application/json' \
  -d '{"ids":[1,2],"updates":{"industry":{"op":"set","value":" 制造业 "},"important_date":{"op":"clear"}}}'
```

## 批量修改

在首页客户列表中勾选若干客户（支持全选、逐条取消），列表上方会显示当前选中的客户编号、名称与数量；没有勾选客户时无法提交。每条记录以客户编号识别，客户名称和编号不参与编辑，也不会新建客户。

四个可修改字段（`source`、`region`、`industry`、`important_date`）各自独立选择操作：

- `keep`（保持原值，默认）：该字段不修改；初次进入编辑时四个字段均为保持原值，此时输入框为空也不会清空资料，也不会用某个选中客户的内容替其他客户填值。
- `set`（设为填写的值）：填写文本去除前后空白；来源、地区和行业保留内部空白与换行；仅含空白的填写值按清空处理。
- `clear`（清空）：清空后该字段与导入时未填写一样，列表中显示为空，接口返回 `null`。
- `important_date` 设为非空值时，沿用导入规则：须为 `YYYY-MM-DD` 格式的真实日历日期（如闰年 2 月 29 日）。

一次提交中，只要出现以下任一情况，整次请求被拒绝（HTTP 400，返回 `{"error": "具体原因"}`），任何客户都不改变：未选择客户；四个字段全部保持原值；日期无效；设置值不是文本；`updates` 中出现四个字段以外的键；客户编号不是正整数；某个编号找不到对应客户。页面会保留勾选和已填写内容供修正，不显示成功。

`ids` 中重复出现的同一客户编号只视为选中一次；原值已符合本次设置的客户仍计入成功处理数量。

成功时返回去重后的处理数量：

```json
{"updated_count": 2}
```

保存成功后，页面明确显示成功处理的客户数量，刷新列表相关列并清除本次勾选；没有被勾选的客户不受影响。重新打开页面或使用原数据目录重启服务后，仍能看到保存结果。

## CSV 导入

在首页选择 CSV 文件并提交后，页面会显示新增数量、未导入数量及逐条原因，列表随即刷新出成功新增的客户；没有客户时仍显示空列表提示。

文件要求 UTF-8 编码（允许开头带 BOM），支持逗号、引号和字段内换行。表头使用 `name`、`source`、`region`、`industry`、`important_date`：

- 只有 `name` 列必须存在，其余列可省略，顺序不限；仅有合法表头时零条新增。
- 缺少 `name` 列、表头重复、出现未知列、编码错误或 CSV 结构损坏时，整份文件拒绝导入（HTTP 400）并说明原因，客户列表保持原样。
- 各字段去掉前后空白；名称必须非空；可选字段省略或为空时视为未填写。
- `important_date` 可以为空，非空时须为 `YYYY-MM-DD` 格式且为真实日历日期。
- 列数不符、缺少名称或日期无效只使该条记录失败，其他有效记录照常新增，报告会说明具体字段及原因。失败记录按原文件的数据记录编号定位（表头不计入编号；带引号字段中的换行仍属于同一条记录）。
- 导入不会更新已有客户。重复判断使用去前后空白后的名称、英文字母不区分大小写（内部空白与标点保持区别）：与已有客户重复时跳过并报告已有客户编号；文件内多条同名有效记录只新增最先出现的一条，后面的记录报告与哪条记录重复。前面记录因字段错误未导入的，不阻止后面同名有效记录新增；重复记录的其他字段即使不同也不会覆盖已保存信息。

成功时（HTTP 200，即使存在失败记录）返回示例：

```json
{
  "imported_count": 1,
  "failed_count": 1,
  "imported": [{"row": 1, "id": 7, "name": "某客户"}],
  "failures": [{"row": 2, "reason": "重要日期无效（2025-13-40）：不是真实日历日期"}]
}
```

文件级错误返回：

```json
{"error": "缺少名称列：表头必须包含 name 列"}
```

`GET /api/clients` 仍保持 `{"clients": [...]}` 外层结构，每条记录含 `id`、`name` 以及 `source`、`region`、`industry`、`important_date`，升级前已有的旧客户这些新增字段为空。

## 测试

接口冒烟测试会启动真实服务（临时数据目录，结束后自动清理），覆盖导入、批量修改与路由的公开行为：

```sh
python3 smoke_test.py
```

首页批量保存的页面层面回归测试（`page_test.mjs`）同样启动真实 `app.py`，再用 Puppeteer 驱动系统 Chrome 打开首页，通过请求拦截分别破坏「保存成功之后的那次列表读取」，验证保存结果与随后读取客户列表的结果分别处理：

- 保存回复确认成功后，即使紧接着的列表读取连接失败、返回非成功状态、内容无法解析或缺少客户数组，页面仍按保存回复的 `updated_count` 明确显示成功处理数量（不按刷新后的记录数重算），并提示列表暂未更新、当前资料可能仍是保存前内容、稍后刷新即可、无需再次保存；
- 保存成功后无论列表是否读到，勾选清除、已选归零，四个字段恢复「保持原值」、输入清空并回到不可填写状态；读取失败时旧表格保留、不显示空列表提示、不重发保存请求，按钮结束等待且无勾选时不可提交；
- 之后刷新或重新打开页面读取成功时显示真实资料并撤下失败提示；真实空列表正常显示空列表提示；
- 保存成功且列表读取成功的正常路径，以及保存被明确拒绝（400）时保留勾选与已填内容、不套用成功后清理的路径，同样在覆盖范围内；
- 保存请求尚未返回（等待期）的行为通过请求拦截「扣住」修改请求固定下来：按钮显示「正在保存…」且不可再次保存，选中信息、字段操作与填写原样保留、不提前显示成功数量；等待期内重复点击、输入框回车或直接触发表单提交都不产生第二次修改请求，等待提示也不被成功或「未选客户」错误替换；等待期内取消/重选客户、勾选第三名客户、调整字段操作与输入都正常体现在页面上但不解除等待，实际修改对象与字段值始终以第一次保存固化的请求为准，结果返回后不自动补交等待期间的改动；400 拒绝时保留返回结果时页面上的勾选与填写、资料不变，等待结束后有选中客户才能再次保存。判定以实际发出的请求次数与请求体、以及后端客户资料结果为准，不仅凭按钮外观。

运行方式（需要 Node 18+ 与系统 Chrome/Chromium；默认使用 `/usr/bin/google-chrome`，可用 `CHROME` 环境变量指定其它可执行文件）：

```sh
npm install          # 只安装 Puppeteer 驱动库，不额外下载浏览器
node page_test.mjs   # 或 npm test
```
